# Refreshing offline vendor references

Run `python3 scripts/update_rf_reference_data.py` from the repository to rebuild `backend/app/data/rf_reference.json` and the lightweight `backend/app/services/ble_company_ids.json` from public registry downloads. Review source sizes, SHA-256 digests, counts and changes to curated overrides before committing. For repeatable checks without re-downloading, `--source-dir DIR` reads files named by their keys in `SOURCES`; `--output /tmp/rf-reference.json` writes a scratch artifact without changing the lightweight lookup. The partial `--local-only` mode requires explicit scratch output and an existing local `backend/app/data/manuf.txt`.

[IEEE publishes MA-L, MA-M, MA-S, IAB and CID](https://standards.ieee.org/products-programs/regauth/). MA-L (/24), MA-M (/28), MA-S (/36) and legacy IAB (/36) identify assigned MAC address blocks. A CID is not an EUI-48 assignment and is not ingested as one. The longest matching prefix wins. The generator also reads the Wireshark and Nmap vendor names and [Bluetooth SIG Company Identifiers](https://bitbucket.org/bluetooth-SIG/public/src/main/assigned_numbers/company_identifiers/). A SIG company identifier belongs to a different namespace from IEEE MAC addresses.

Only reference lists are downloaded; observed addresses are never sent to a vendor lookup service. A registry hit identifies an assignee, not a device model, person, camera, microphone or recording. As of the November 15, 2026 snapshot, `9C:06:CF` is a PLAUD Inc. MA-L assignment; it is vendor context only. The phone and badge keep small curated tables; they do not ship the entire backend registry. In the Android app, only the drone role with a non-ambiguous prefix can produce an OUI-only drone suggestion. Additional hardware aliases must not infer a branded product from addresses shared by an ODM, chipset supplier or unrelated company with a similar name.
