# iPhone coverage and known gaps

The native iPhone app requires iOS 17 or later. It opens to **Privacy → Recorders** after the welcome screen. This comparison uses the Android Google Play candidate `73badb6` as its baseline. “Implemented” refers to code in this repository. Recognition on specific hardware still needs the device checks below. [Android candidate](https://github.com/lnxgod/friendorfoe/tree/73badb6d354f0097afc6602070dce38e530a9d96/android) · [iPhone implementation](../ios/FriendOrFoe/)

## What works on iPhone

| Area | Behavior in this build |
| --- | --- |
| Personal recorders | Start a foreground Bluetooth scan. The eleven recorder families are Plaud (including NotePin), Omi, Limitless, Bee, Friend, Fieldy, viaim RecDot/OpenNote, soundcore Work, Notta Memo, Instamic and DJI Mic 2/3. Plaud depends on a recognizable broadcast name. Omi, Limitless, Bee and Friend can also match a service UUID. Findings show what matched, when it was seen and signal strength when available. **Recording status is unknown.** The offline name example lets you try the rules without a scanner. |
| Finding a device | Search observations, switch among Recorders, Nearby, Beacons and All, or filter recorder results by family and source. The Privacy page also shows recorder reports from a configured station. AirPods and other everyday accessories collapse into a drill-down. Save an observation, ignore a phone identifier or clear local history. Ordinary phone sightings stay in memory. |
| Other Bluetooth devices | Selected broadcasts can identify camera, smart-glasses and tracker families. A qualifying legacy Bluetooth Remote ID Basic ID packet produces a presence finding. It does not place a drone on the map. A name or advertisement can be imitated. Visibility changes when a device is renamed, connected or silent. [Apple advertisement fields](https://developer.apple.com/documentation/corebluetooth/advertisement-data-retrieval-keys) |
| iBeacons | Add a known proximity UUID and start ranging with location permission. The phone groups results by network and shows individual major/minor values on drill-down. The Station tab can group previously unknown UUIDs observed by compatible scanner hardware. [Apple iBeacon guide, p. 4](https://developer.apple.com/ibeacon/Getting-Started-with-iBeacon.pdf#page=4) |
| Station and Wi-Fi | Connect a compatible Friend or Foe HTTPS server. Refresh its device and Wi-Fi feeds, search, filter by category and inspect scanner evidence. A Wi-Fi alert leads with its SSID or “SSID unavailable,” then explains the trigger. The sightings describe the scanner's surroundings. The address is saved on this iPhone and can be forgotten. Reports stay in memory. A separate badge diagnostics link opens read-only status in the browser after you join the badge’s Wi-Fi. [Station implementation](../ios/FriendOrFoe/Station/) |
| Nearby and Map | Allow the aircraft lookup to send a search center rounded to 0.1° to adsb.lol. Distances are measured from that center. Choose a range from 1 to 50 miles, search aircraft, filter airborne/ground reports, open details or view trails on Apple Maps. Refresh manually or enable one-minute updates while using these screens. Recent trails cover up to 30 minutes. Save up to 100 flight snapshots locally. The provider sees the search area and IP address, and Apple Maps can receive the viewed area. [Aircraft provider and attribution](https://www.adsb.lol/docs/open-data/api/) · [MapKit](https://developer.apple.com/documentation/mapkit/mapkit-for-swiftui) |
| More and appearance | Search the bundled aircraft and drone reference guide offline. Lens inspection offers a camera preview, bright-area highlighting and a torch on supported devices. Sound check shows microphone levels and energy between 18 and 22 kHz. An opt-in magnetic-field check measures the local field using calibrated phone sensors. These tools run on the phone and store no frames, audio or magnetic readings. Reflections, sound levels and magnetic readings require interpretation. System, Light and Dark appearance, GameChangers AI credit, the GitHub source link and privacy disclosures are available in the app. [More implementation](../ios/FriendOrFoe/More/) |

## Why Android and iPhone differ

| Android capability | iPhone limit or remaining work |
| --- | --- |
| Nearby Wi-Fi networks, vendor prefixes and Wi-Fi drone broadcasts | **Platform limit.** Ordinary iOS apps have no general-purpose Wi-Fi scanner or packet-capture interface. Core Bluetooth supplies an Apple-assigned peer identifier in place of the Bluetooth MAC address used for Android vendor-prefix matches. Adding more OUIs to the iPhone app would not supply those missing addresses. A compatible external station can supply observations. [Apple Wi-Fi API overview](https://developer.apple.com/documentation/technotes/tn3111-ios-wifi-api-overview) · [Apple Bluetooth peer identifiers](https://developer.apple.com/documentation/corebluetooth/cbpeer/identifier) |
| Unknown beacons, repeated encounters and background alerts | **Platform limit and implementation choice.** iPhone ranging needs a known iBeacon UUID, and iOS can coalesce Bluetooth events in the background. This build stops scanning in the background. Continuous encounter alerts and Android’s broader tracker coverage are absent. Apple’s system unwanted-tracker notifications operate separately. [Apple iBeacon guide](https://developer.apple.com/ibeacon/Getting-Started-with-iBeacon.pdf) · [Apple background Bluetooth behavior](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html) · [Apple unwanted tracking alerts](https://support.apple.com/en-us/119874) |
| Aircraft and drone tools | **Remaining port work.** The iPhone uses one aircraft provider. Android has additional providers, enrichment, AR sky overlays, alerts and richer history. Drone identification from additional packet formats, drone positions from a station and combined aircraft/drone maps are outside this build. The offline reference guide can be used independently of live observations. |
| Android inspection and hardware controls | **Remaining port work and accessory constraints.** The iPhone measures the local magnetic field. Android’s broader probe tools and plugins, scanner calibration, capture review and USB badge controls have not been ported. The badge status link is read-only. Additional transports require compatible hardware and supported iOS APIs. [Apple guidance on USB accessories](https://developer.apple.com/forums/thread/802640) |

## Before TestFlight and App Store submission

- [ ] Install a signed build on a physical iPhone. Check the first launch, permission denial and recovery, Light/Dark/System appearance, large text and VoiceOver in the five tabs.
- [ ] With a known recorder and Android handset side by side, compare visible names/services while idle, connected and recording. Log model, firmware, OS, state and match evidence. Repeat for each family before advertising verified coverage. Confirm AirPods stay collapsed, filters isolate recorder reports, and saved and ignored observations behave after relaunch.
- [ ] Range two beacons with one known UUID and different minor values. Check grouping, stop/resume and location denial. Use a separate station report to check an unfamiliar UUID.
- [ ] Connect a test station with known Wi-Fi and recorder observations. Check SSID present, SSID missing, evidence, stale data after disconnect, source filtering and forgetting the address. Check badge status on the badge network.
- [ ] Exercise aircraft lookup with approximate location, with permission denied and offline. Confirm aircraft distances, marker details, saved flight persistence/deletion and that backgrounding stops auto-refresh. Test camera/torch and microphone with permission granted and revoked, including hardware or audio routes with limited high-frequency response.
- [ ] Run the magnetic-field check on an iPhone with motion sensors. Check the reading changes near an ordinary magnet and that leaving the tool stops measurement. Check how the screen handles unavailable or uncalibrated readings.
- [ ] Reconcile App Store Connect privacy answers with actual data flows, prepare review instructions for hardware-dependent features, and run internal TestFlight before submission. The GitHub link is for source code. Distribution and updates for an App Store build use Apple’s store.
